# 團班點名系統（Firebase 版）

網頁放在 GitHub Pages，資料存在 Firebase（Firestore），登入用 **Email＋密碼**（帳號由主管在網頁上建立）。
功能和 Apps Script 版相同：點名、補課、總表、名單、試聽轉正／不續班、續費提醒、調課停課、月結（含分校人數與分校負擔）、四級權限。
原本要在試算表上做的設定（班級、帳號、系統設定），改到網頁的「管理」分頁；報表可以下載成 Excel。

> 想先看看畫面：網址後面加 `?demo` 就是示範模式（虛構資料，只存在瀏覽器，重新整理就還原）。

## 檔案

| 檔案 | 用途 |
|---|---|
| `index.html` | 網頁本體 |
| `js/config.js` | **安裝時要改**：Firebase 設定、擁有者 UID |
| `firestore.rules` | **安裝時要改**：資料庫安全規則（貼到 Firebase 主控台） |
| `js/logic.js` | 計算邏輯（應到、薪資、分攤、續費、補課結算），和 Apps Script 版一模一樣 |
| `js/api.js` | 各功能與權限判斷 |
| `js/accounts.js` | Email、密碼格式檢查 |
| `js/store.js`、`js/backend-*.js` | 讀寫 Firebase |
| `js/export.js` | 下載 Excel |
| `js/demo.js`、`js/main.js` | 示範資料、啟動流程 |

## 安裝（約 20 分鐘，只要做一次）

### 一、建立 Firebase 專案
1. 到 [Firebase 主控台](https://console.firebase.google.com/) →「新增專案」，名稱例如 `roll-call`。Google Analytics 可以關掉。方案用免費的 Spark 就夠。
2. 左側「建構 → Authentication」→「開始使用」→「登入方式」→ 啟用 **電子郵件/密碼**。
3. 「Authentication → 使用者」→「新增使用者」，填你自己的 Email 和密碼（至少 8 字、英文＋數字）。建立後，**複製那一列的「使用者 UID」**。
4. 左側「建構 → Firestore Database」→「建立資料庫」→ 位置選 `asia-east1（台灣）` →「以正式版模式啟動」。

### 二、貼上安全規則
5. 打開 `firestore.rules`，把 `"請貼上你的UID"` 換成第 3 步複製的 UID（保留雙引號）。
6. Firebase「Firestore Database → 規則」，把整份內容貼上，按 **發布**。

### 三、填設定檔
7. Firebase「專案設定（齒輪）→ 一般 → 你的應用程式」→ 點 `</>` 新增網頁應用程式（不用勾 Hosting）。畫面會出現一段 `firebaseConfig`。
8. 打開 `js/config.js`：
   - 把那段設定值貼到 `firebaseConfig` 裡。
   - 把第 3 步的 UID 貼到 `OWNER_UIDS` 裡。
   - `apiKey` 公開沒關係，資料安全靠第二步的安全規則把關。

### 四、放上 GitHub Pages
9. 在 GitHub 新增一個 repo，例如 `rollcall`，把這個資料夾裡的所有檔案上傳，`js` 資料夾也要一起上傳。
10. repo 的「Settings → Pages」→ Source 選 `Deploy from a branch`，分支選 `main`、資料夾選 `/ (root)` → Save。
11. 約 1 分鐘後就能用：`https://skyyuuuuu.github.io/rollcall/`
12. 回到 Firebase「Authentication → 設定 → 授權網域」→ 新增 `skyyuuuuu.github.io`。少了這步，「忘記密碼」寄出的連結會出問題。

### 五、開始使用
13. 用第 3 步的 Email 和密碼登入，你就是主管。然後到「管理」分頁：
    - **設定**：分校名稱、續費提醒堂數等。
    - **班級**：新增班級，按「儲存並產生堂次」。
    - **帳號**：幫每位同事開帳號，填 Email（本人常用的信箱）、角色、分校、可點班級。系統會自動產生一組初始密碼，請轉告本人，對方登入後可以按右上角「密碼」自己改。
14. 到「名單」分頁加入學生，就可以開始點名。

## 批次新增班級、學生

開學一次要建很多班、加很多學生時，可以用 Excel 一次匯入。

| 功能 | 位置 | 誰能用 |
|---|---|---|
| 批次新增班級 | 管理 → 班級 →「批次新增」 | 主管 |
| 批次新增學生 | 名單分頁最下方「批次新增學生」 | 主管、分校行政（限自己分校） |

1. 按「下載範本」，照範本格式填好。也可以用自己的 Excel，只要第一列有標題（例如：姓名、校區、班級、電話），系統會自動對上欄位。
2. 兩種匯入方式擇一：
   - 在 Excel 選取表格（可以含標題列）→ 複製 → 貼到網頁的框裡。
   - 按「上傳 Excel／CSV」。
3. 按「檢查」，系統會逐列列出 ✓ 可匯入，或 ✗ 哪裡有問題（例如開課日不是那個星期、班級名稱重複、找不到班級、分校寫錯）。
4. 確認沒問題後按「匯入」。有問題的列不會匯入，改好再檢查一次就好。

**班級欄位：** 班級名稱、星期、時段、開課日、預計堂數、薪資規則、講師、停課日期、備註。
- 星期可以留空，系統會照開課日判斷；也可以寫「一」「週一」「1」。
- 可以勾「匯入後直接產生堂次」。

**學生欄位：** 學生姓名、分校、班級、身分、加入日、家長聯絡、備註。
- 同一位學生上好幾個班，班級欄用「、」分開，例如 `國一數學班(一)、國一英文班(五)`。
- 身分留空就是正式生；加入日留空就是今天。
- 已經在名單裡的會自動略過，不會重複新增。
- 分校行政的分校欄可以留空，系統會自動填自己的分校。

批次新增也會寫進操作紀錄。

## 批次修改開始上課日

只能改在班的正式生。試聽生要用「轉正」設定正式上課日，已退班的學生不能改。可以使用的人是主管和分校行政，分校行政只能改自己分校的學生。

- **全部改成同一天：** 到名單分頁選一個班，按「批次改開始日」，勾選學生（或按全選）並選日期。按「檢查」看預覽，確認後按「修改」。
- **每人日期不同：** 打開名單分頁最下方的「批次修改開始上課日」，按「下載範本」。範本會列出目前所有在班正式生和他們現在的開始日，只要改日期欄再上傳就好，日期沒變的列會自動略過。
- **新日期比原本晚：** 如果原日期到新日期之間已經有點名，預覽會提醒「改完那幾堂不再算他」。那幾堂就不會再算進他的應到、計薪和剩餘堂數。
- **曾經是試聽生的學生：** 只改正式上課日，試聽的加入日會保留。

**已結算月份：** 主管可以在「月結」頁按「把 X 月（含以前）標記為已結算」，也可以在「管理 → 設定」填「月結已結算至」。設定之後，下面兩種情況都不能改：

- 新日期落在已結算的月份。
- 原本的開始日落在已結算的月份。

這樣才不會改到已經發出去的應到人數和薪資。按錯了可以在月結頁按「取消結算」。目前這個鎖只管開始上課日的修改，不影響點名和補課。

修改和結算設定都會寫進操作紀錄。

## 權限

| 功能 | 主管 | 分校行政 | 老師 | 助教 |
|---|---|---|---|---|
| 點名、新增試聽生 | ✓ | ✓ 整班 | ✓ | ✓ |
| 補課登記／取消 | ✓ | 限自己分校學生 | ✓ | ✗ |
| 總表 | ✓ 含薪資 | ✓ 只顯示自己分校負擔 | ✓ 無薪資 | ✗ |
| 名單、試聽轉正／不續班、續費 | ✓ | 限自己分校學生 | ✗ | ✗ |
| 月結 | ✓ 全部，可設補課統計截止日 | 只看自己分校負擔 | ✗ | ✗ |
| 總覽、調課／停課 | ✓ | ✓ | ✗ | ✗ |
| 管理（班級、帳號、設定、操作紀錄、全部資料備份） | ✓ | ✗ | ✗ | ✗ |

除了網頁畫面會擋，Firestore 安全規則也會再檢查一次。例如老師讀不到薪資規則和繳費紀錄，分校行政也寫不進其他分校的名單和繳費紀錄。

## 跟 Apps Script 版的差別

- **登入**：PIN 改成每人一組 Email＋密碼。忘記密碼可以在登入頁按「忘記密碼？」收信重設，主管也能在「管理 → 帳號」幫忙寄重設信。
- **員工離職**：在「管理 → 帳號」取消勾選「啟用」，那個帳號就馬上不能使用。
- **試算表**：不用再開試算表。月結、點名總表、全部資料備份都在網頁上按一下就能下載成 Excel。建議每月下載一次備份。
- **Safari**：不會再出現「無法開啟這個檔案」的問題。
- **每日 LINE 提醒**：這一版沒有。Firebase 要做定時推播，得升級成付費方案才能用 Cloud Functions。目前改看「總覽」分頁的未點名、補課、續費數字。
- **舊資料**：沒有搬過來，新學期直接在新系統建班。

## 操作紀錄

主管在「管理 → 操作紀錄」可以查看誰在什麼時候做了什麼，可以篩選期間、人員、類別，也能搜尋或下載成 Excel。

| 類別 | 會記錄的動作 |
|---|---|
| 登入 | 登入系統 |
| 點名 | 點名、修改點名（列出誰從什麼改成什麼、取消了哪些） |
| 補課 | 登記補課、取消補課 |
| 名單 | 新增學生、現場新增試聽生、轉正、不續班、退班、取消退班／轉正 |
| 續費 | 已開單、已續費、設定期初堂數、取消繳費紀錄 |
| 調課 | 調課、停課順延、恢復上課 |
| 月結 | 設定補課統計截止日 |
| 管理 | 新增／修改／刪除班級、產生堂次、新增／修改帳號（含角色、權限、啟用的變更）、修改系統設定 |

- 紀錄寫入後不能修改，也不能刪除，連主管也不行；而且只有主管看得到。
- 每筆紀錄綁定操作人的登入身分，不能冒用別人的名字。
- 限制：紀錄是由網頁在操作時順便寫入的。懂技術的人若用自己的有效帳號、繞過網頁直接改資料庫，就不會留下紀錄。要做到完全無法繞過，需要伺服器端程式（Cloud Functions，付費方案）。一般使用情境不會有這個問題。

## 資安

- 密碼由 Firebase Authentication 保管：加密雜湊儲存，連續猜錯會自動暫時封鎖。網頁、資料庫和主管都看不到密碼本身。
- 密碼規定至少 8 個字元，要同時有英文和數字。
- 就算有人自己註冊了登入身分，沒有主管建立的帳號資料就是「未啟用」，什麼都讀不到。
- 員工離職時取消「啟用」，下一次操作就會被擋下。
- `js/config.js` 裡的 `apiKey` 是公開的設計，資料安全靠 Firestore 安全規則把關。
- 共用電腦用完請按「登出」。

## 免費額度

Spark 方案每天有 5 萬次讀取、2 萬次寫入。這個系統每位使用者登入時讀一次全部資料，大約是「班級數＋名單人數＋已上堂數」筆，之後只讀有變動的部分。以目前的規模（十幾位同事、幾個班）用不到額度的零頭。

## 常見問題

| 狀況 | 處理方式 |
|---|---|
| 登入後顯示「帳號尚未啟用」 | 主管還沒幫你開帳號，或帳號被停用了 |
| 顯示「沒有權限」 | 確認 `firestore.rules` 已經發布，而且 UID 跟 `config.js` 裡的一樣 |
| 畫面顯示「尚未設定 Firebase」 | `js/config.js` 還沒填，或忘了上傳到 GitHub |
| 改了檔案但畫面沒變 | GitHub Pages 約 1 分鐘才會更新；手機上把頁面重新整理 |
| 同事忘記密碼 | 登入頁按「忘記密碼？」收信；或主管在「管理 → 帳號 → 編輯」按「寄重設密碼信」。沒收到請看垃圾郵件匣 |
